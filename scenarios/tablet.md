# Tablet
## Hypothetical context
A tablet may offer a browser and restricted local execution; exact capabilities are unknown.

## Human objective
Review and generate a project artifact with limited keyboard interaction. The human must specify quality, time and operating constraints before execution.

## What does the human have?
Check operating system, file access, input methods, available apps, network and accessibility needs. Treat historical inventory as provisional until relevant checks pass.

## What can the whole system accomplish?
Prefer existing accessible interfaces and reduce repetitive manual entry; consider authorized remote work only if necessary. Record untested combinations as UNKNOWN; avoid installing a standard stack by default.

## Acceptance and failure
Verify creation, editing, export and retrieval through the tablet's actual interface. A remote artifact that cannot be retrieved or edited on the tablet fails the objective.

## Research comparison
Compare feasible strategies at equal acceptance quality, including setup, supervision, recovery and resource costs. This scenario supplies no measured benefit and authorizes no environment changes.
